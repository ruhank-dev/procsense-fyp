# Problem discovery rules: review pack for a clinician

_Generated by `tools/content/build_discovery.py`; do not edit by hand._

**Status: not reviewed by a clinician.** Each rule says what the trainee must have seen or done before a problem of the case joins the problem registry (a result opened, an examination finding, a history topic, a flag the engine set). The 29 rules of the 17 P0 cases were written one by one from the case content; the other 127 were derived from the same content by a fixed reading (the words of the problem name the evidence, and the evidence must exist in that case), so they are consistent with the case but are the project's reading, not a clinical judgement. A clinician is asked to confirm or change each (`docs/research/clinician_signoff.md`, Q10). Changing a rule never changes a case file or its approval.

Internal checks that pass today: every problem of every case has a rule (except the two framing problems of the fit patient), every rule names only facts the engine keeps, every derived rule points at evidence that exists in its case, and the rule is false on an empty state and true once its evidence is there (`DiscoveryTests.cs`).
