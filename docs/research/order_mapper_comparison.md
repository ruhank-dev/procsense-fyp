## Where the time of one hearing goes (16 development orders; `tools/ai/profile_orders.py`)

| compact | 1.94 | 3254 / 3534 | 844.7 (138) | 2271.9 (428) | 140.9 |
| lean-parallel2 | 2.0 | 4081 / 60056 | 1037.0 (139) | 2851.4 (523) | 173.5 |

| short | 2.25 | 2762 / 4653 | 600.6 (98) | 1948.0 (332) | 139.7 |

Reading: nearly all the time is the host evaluating the prompt (about 4 ms a token on the desktop card) plus a few hundred milliseconds of generation; serialization and the network hop are under 2 ms a call and the Python around the calls is 140 ms (it was 266 ms before the grammar skipped fuzzy comparisons that cannot reach the threshold). Two parallel host slots did not let the host reuse an evaluated list between hearings (the prompt token counts did not fall) and produced a 60 s stall once, so it was dropped. The agreement rule makes about a fifth of the hearings three calls; that tail sets the 95th percentile.
