## What was built

* One local model call per utterance (`qwen3.5:4b-q4_K_M`, digest `d8b0f5e9760c`, matches `content/assessment/thresholds.json`: True; Ollama 0.40.5, llama.cpp runner, thinking OFF, temperature 0, seed 7, at most 2 findings, 160 output tokens). All 19 objectives (the approved acts of `taxonomy.json`, their definitions verbatim) are eligible at every call because the benchmark rows carry no scenario state; `rubric_eval.eligible(step)` also reads the behaviour windows of `mapping.json` but kept out-of-window objectives eligible, which is NOT the engine's rule (`EvidenceStore.Submit` rejects them as CONTEXT_MISMATCH; corrected 19 Oct 2026, ADR-0022); the frozen results used all objectives and are unaffected.
* Result schema per finding: objective, verdict (SUPPORTED / NOT_SUPPORTED / UNCERTAIN), actor, modality, evidence, reason code. Omitted objectives count as NOT_SUPPORTED. Evidence must be a verbatim part of the utterance; a defective finding is recorded and dropped, never repaired.
* Interpretation and credit are separate (`rubric_eval.evaluate` / `credit`). A critical objective is never credited from speech. The production gate was not modified: the baseline is its recorded decisions, and the production critical-cue and non-assertive checks are called unchanged where stated.

* **Baseline reconciliation (checked, not assumed).** The gate was re-run unchanged on all three splits (`tools/bench/nli_baseline.py`). On test2 it reproduces the committed `reports/ai/act-benchmark-test2.json` exactly (72 credited, 69/140 legitimate, 0/40 critical, 0/300 non-assertive). On test the committed `act-benchmark.json` still records the gate BEFORE the assertion check was widened (92 credited, 70 legitimate, 22/300 non-assertive credited); the gate as it stands now credits 70 (66/140 legitimate, 0/300), because the widening was written from that split's failures (ADR-0020). The test baseline here is therefore the current gate, optimised on test.

**Thinking.** The Ollama `think: false` option is supported for this model and behaves as claimed: 3 calls returned no thinking text ([0, 0, 0] characters) and only the JSON tokens ([47, 87, 60]). With the option omitted (or true) the model thinks by default: all 3 calls spent the whole 160-token cap on thinking and returned EMPTY content (done_reason length). Every benchmark call used `think: false`; none carried thinking text.

**Budget.** The documented target is a p95 voice round trip under 4.0 s (feature C31) and a 3 s timeout for a live model call (`unity_ai_hooks.md`). Recognition takes 1.021 s at p95 and the first spoken sentence 2.19 s (both read from the committed reports, not re-measured), which leaves 0.79 s for everything between them. The evaluator adds 3.35 s median and 4.13 s p95 if it runs in the reply path: it does not fit (serial_in_the_reply_path_fits = False), and it exceeds the 3 s live-call timeout on its own. Run beside the reply, it still queues in front of the patient's reply on the single model slot (ADR-0011). Speech recognition was not re-measured here, and no Unity-side time exists (no headset run).
