# P0 release v1.0 (p0-evaluation-performance-s08, EXP-REL-1, EXP-REL-2)

Status: **prepared, not released.** P0 is finished when two things are true:

- someone else rebuilds it from the README on a clean machine in at most 2 hours (EXP-REL-1, T-Q2);
- it runs 10 full sessions on the Quest without a crash and within the perf gate (EXP-REL-2).

The steps that make a tagged build are in [`docs/RELEASE.md`](../RELEASE.md). This page adds what v1.0 needs on top of them and holds the evidence.

## EXP-REL-2: ten full runs on the Quest

Each run plays one full case from boot to the debrief on the Demo build, with OVR Metrics recording. Afterwards the logs are pulled and replayed headless:

```
uv run --project tools tools/unity/quest_sessions.py pull
uv run --project tools tools/unity/quest_sessions.py replay
```

Each run's CSV is summarised with `task perf-row`.

## Release notes (draft for v1.0)

ProcSense P0 is a VR simulator for the pre-operative path of the two P0 scenarios: S1, elective laparoscopic cholecystectomy, and S2, the emergency abdomen. All patients are synthetic. It is for education, not for patient care.

**What a trainee can do:**

- confirm identity, with the wristband, the notes and the nurse when the band is wrong or missing;
- take observations on a live monitor, with alarms;
- take a history and examine;
- order tests, send samples and read results, including the critical-result phone call;
- read the EMR and the patient folder;
- go to imaging and come back;
- lead the ward checklist and the WHO Sign In and Time Out;
- make the case decision.

The session ends with a debrief that names each finding's source.

**Practice and assessment.** Practice mode gives hints and shows the identity status. Assessment mode does neither and offers only approved cases.

**Every session can be checked.** A session log replays headless to the same hash, so any session can be verified.

**Known limits.** See the open items of each step in `docs/plans/task-reconciliation.md`. These include the ECG and capnography traces, which wait for the engine to publish them, and the external acceptance checks still to run with users and the medical reviewer.

## Tag

The owner creates the tag on the commit the APKs were built from:

```
git tag -a v1.0.0 -m "ProcSense P0"
```

Then pushes it:

```
git push origin v1.0.0
```

The tag, commit, checksums and perf CSV then go in the Releases table of `docs/RELEASE.md`.
