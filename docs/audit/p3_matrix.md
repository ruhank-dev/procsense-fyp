## 0. Headline findings

1. **The whole game flow is not reachable in the shipped build.** `MenuFlow` and `FlowPanel` (Unity/Assets/Scripts/Flow) are constructed only in `Tests/PlayMode/MenuFlowTests.cs`. A grep of every `*.cs` under `unity/Assets` finds no runtime or Editor installer; `FlowPanel.cs.meta` GUID `da5b1670...` appears in no scene or prefab. `MenuFlow.Current` is therefore always null in a player, so `DemoLoginView.Finish()` (`?.SignedIn()`) does nothing and `SpokenActionRouter` (line 85) never takes the hint/submit voice road.
2. **The shipped path is the older one:** Boot -> login -> `Sys_Core` + `PatientBay` with `SessionConfig_Skeleton1.asset` (`caseId: VAR-S1-A`, `seed: 42`, `mode: 0` practice). `MainMenu.unity` is in the build list but nothing loads it (BootLoader scenes = Sys_Core, PatientBay); `MainMenuController` only loads Boot. No procedure selection, no random case, no Submit to OT button, no Retry in the player.
3. **Examination pool (was empty; fixed 14 Nov 2026 in Core and content).** 63 playable cases are now `APPROVED_FOR_ASSESSMENT` as owner-attested approvals (ADR-0032 D1; no clinician named or signed) and the loader rule needs that attestation for non-P0 cases. Unity tests that encoded the empty pool (`MenuFlowTests.The_examination_starts_only_a_case_approved_for_assessment` and four others) still need updating and a Unity run (DT-297).
4. No secrets found in `unity/Assets/Scripts`, `StreamingAssets/content`, `Resources`, `Editor`, `Data`, `ProjectSettings` (patterns `sk-`, `AIza`, `service_role`, `OLLAMA_API_KEY`, long Bearer tokens; no `.env*` under `unity/` depth 3). Server keys are `SecretStr` settings (`server/config.py`).
