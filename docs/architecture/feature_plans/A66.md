## 1. Intended user experience

Authors can browse what the system knows (which findings go with which conditions, which decisions lead to which consequences, and the source of each); the composer only uses relationships recorded there.

## 2. What exists and what is missing

**Exists in the repository:**

- case files, walkthrough-derived tables (bands, critical results, findings, decision rules, what-ifs), source register, derived dataset aggregates

**Missing:**

- typed knowledge graph
- relation extraction from cases and walkthrough
- statistical relations from datasets
- confidence and limitation notes

**Deterministic foundation:** Each relation carries source ids and a confidence; authors review extracted relations before release.

## 3. The AI in this feature (seven questions)

| Question | Answer |
|---|---|
| 1. What is the AI supposed to do? | Extract candidate relations (condition-finding, test-finding, decision-consequence) from case files and walkthrough text. |
| 2. Why is AI useful here? | Hundreds of relations are implicit in prose and tables; an LLM extracts candidates far faster than hand-coding. |
| 3. Which method for which part? | LLM extraction with schema; statistical estimation of strengths from datasets; deterministic merge and review. |
| 4. Deterministic parts still needed | Schema, merge, review, outlier handling (statistical outliers are not treated as abnormalities without a band or source). |
| 5a. AI already implemented | None. |
| 5b. AI missing | Extraction pipeline. |
| 6. What we must build | Extraction prompt, relation schema, dataset strength estimator, review tool. |
| 7. How we prove it beats a simple baseline | Precision and recall of extracted relations against a hand-labelled sample versus keyword rules. |
