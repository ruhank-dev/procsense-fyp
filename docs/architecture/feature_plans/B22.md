## 1. Intended user experience

In practice mode, after opening a result, the trainee can ask 'what does this mean?' and gets a short explanation tied to the report and reference ranges; in the debrief, each key result is explained.

| Field | Value |
|---|---|
| Kind | AI (LLM + retrieval) |
| Status | Proposed new feature |
| Purpose | Explain results. |
| Architecture and model or algorithm | Qwen3.5 9B with report and band facts. |
| Models | MC-04 |
| Data | ST-IMAGING; ST-BANDS |
| Input schema | `InterpretRequest{result_id, trainee_level}` |
| Output schema | `Explanation{text, fact_ids[]}` |
| Processing flow | fetch facts → prompt → validator → show |
| Validation of outputs | Grounding validator; fact ids. |
| Errors | Timeout or server error: one retry, then show the report sentence; logged with prompt version and model digest. |
| Hallucinations | Output must match a JSON schema whose enums are approved ids; the grounding validator rejects invented drugs, values, diagnoses, events and hidden facts. |
| Inconsistent results | Output is cross-checked against the structured case or facts it was given; any mismatch rejects it. |
| Model unavailable | Feature switch reports off; show the report sentence. The session never waits on the model. |
| Invalid input | Inputs are schema-validated before the model is called; invalid input is a 4xx with field errors. |
| Tests | grounding mutation set |
| Metrics | helpfulness rating; escapes (0) |
| Baseline comparison | Report sentence. |
| Acceptance | Helpfulness higher than baseline; zero escapes. |
