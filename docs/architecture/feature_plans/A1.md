## 1. Intended user experience

A content author asks the composer for new S1 or S2 cases with a target difficulty and competencies; within minutes they receive validated case files, each with a Stage B report, a solver trace and the AI's rationale, ready to add to the practice pool.

## 2. What exists and what is missing

**Exists in the repository:**

- Stage B validator (11 checks, 12 contradiction types) and 60 of 60 mutations rejected (tools/composer)
- 53 case files used as source material
- difficulty dimensions and case tags

**Missing:**

- block library with requires and excludes (s01)
- deterministic solver (s02)
- LLM Stage A proposals (s03)
- AI scenario plan composer shared with live generation (p1-live-scenario-generation-s13)
- batch composition run (s05)

**Deterministic foundation:** Stage B validation, case-file schema, difficulty tags: they decide validity. The composer may never mark a case approved.

## 3. The AI in this feature (seven questions)

| Question | Answer |
|---|---|
| 1. What is the AI supposed to do? | Propose whole-case plans (problem mix, investigations, decision points, traps, events, outcomes) that meet teaching objectives, plus the narrative. |
| 2. Why is AI useful here? | A model can combine evidence from 53 cases and the knowledge base into many coherent plans faster than an author and can explain each choice; a solver alone enumerates valid but formulaic combinations. |
| 3. Which method for which part? | LLM with retrieval and schema-constrained output proposes the plan; the deterministic solver completes and checks constraints; Stage B validates; statistical and retrieval generators fill values and media. |
| 4. Deterministic parts still needed | Solver (requires/excludes), Stage B, approval status gate, seeded reproducibility. |
| 5a. AI already implemented | None (Stage B is deterministic). |
| 5b. AI missing | Stage A proposal step, the AI scenario plan composer, the narrative fill. |
| 6. What we must build | Prompt and enum schema over approved block and KB concept ids; retrieval of exemplar cases; avoid-hint loop from Stage B defects; evaluation against the solver-only baseline. |
| 7. How we prove it beats a simple baseline | Blind comparison on 40 cases: AI-composed versus solver-only, rated by two raters on coherence, teaching value and variety; AI must win on teaching value and variety with no loss of Stage B pass rate. |

### A1.c2 — Stage A AI proposals and scenario plans

| Field | Value |
|---|---|
| Kind | AI (LLM + retrieval) |
| Status | Blocked |
| Purpose | Propose coherent case plans and narratives from objectives and evidence. |
| Architecture and model or algorithm | Qwen3.5 9B served by Ollama, JSON-schema output with enums of approved ids, retrieval of KB subgraphs and exemplar cases, temperature 0.7 to 0.8, dedupe by block-set hash. |
| Models | MC-01 |
| Data | ST-BLOCKS; ST-KB |
| Input schema | `ProposalRequest{objectives, difficulty_vector, avoid_hints[], kb_subgraph, exemplars[]}` |
| Output schema | `ScenarioPlan v1 {family, primary_problem{id,type}, secondary_problems[{id,type}], comorbidities[], medications[], allergies[], investigations[{test_id, expected_finding_tags[], band_targets{analyte:band}}], decision_points[{id, step, correct_option_ids[], trap_option_ids[]}], events[{event_id, trigger, window_s}], branches[{decision_id, option_id, consequence_id}], outcomes[{end_state, conditions}], teaching_points[], rationale_per_choice{}}` |
| Processing flow | retrieve KB subgraph and exemplars → prompt with allowed ids only → schema-validate → solver completes missing slots and checks constraints → Stage B → on defect: one retry with the defect as avoid-hint |
| Validation of outputs | Enum schema (T-SA1/T-SA4), solver constraint check, Stage B, grounding validator on narrative. |
| Errors | Timeout or server error: one retry, then solver-only composition with template narrative; logged with prompt version and model digest. |
| Hallucinations | Output must match a JSON schema whose enums are approved ids; the grounding validator rejects invented drugs, values, diagnoses, events and hidden facts. |
| Inconsistent results | Output is cross-checked against the structured case or facts it was given; any mismatch rejects it. |
| Model unavailable | Feature switch reports off; solver-only composition with template narrative. The session never waits on the model. |
| Invalid input | Inputs are schema-validated before the model is called; invalid input is a 4xx with field errors. |
| Tests | T-SA1 to T-SA4; EXP-COMP-1 (0 auto-approved); blind comparison against solver-only |
| Metrics | first-try schema validity; Stage B pass rate; distinct block sets in 20 proposals; rater scores |
| Baseline comparison | Solver-only composition with random seeds. |
| Acceptance | At least 95 percent schema-valid; at least 12 distinct block sets in 20 proposals; rater teaching-value score higher than baseline (paired test p under 0.05). |
| GTX 1660 SUPER (desktop) | Runs as a batch job on the desktop; larger models (8B with offload) acceptable because time is not critical. |
| RTX 4050 Laptop | Batch job when Unity is not running. |
| Memory | CPU offload uses system RAM; keep batch size small on 16 GB. |
| Latency | Offline; minutes per batch acceptable. |
| Deployment | Offline CLI on either machine; results stored and versioned; optional remote GPU for large batches. |
| Tasks | p1-scenario-composer-difficulty-s03; p1-live-scenario-generation-s13 |
