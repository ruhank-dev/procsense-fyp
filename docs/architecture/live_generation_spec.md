# Live scenario generation — specification

_Generated by `tools/plans/pipeline_docs.py` from `procsense_full_pipeline.json` — do not edit by hand._

Goal: every practice session can start on a **fresh** scenario: a coherent, evidence-informed combination the trainee has not met, built from the existing cases and datasets (used as templates, evidence and evaluation material) and validated before it is shown. Randomness is not realism: every value comes from a profiled distribution, every image from a tagged library, every combination from blocks with requires and excludes.

Planning only (12 October 2026): the stages below are specified, not built, unless their status says otherwise.

## 1. Principles

1. **Offline preparation is separate from live generation.** Profiling, the knowledge base, packs, learned models, indices, prompts and model preparation happen offline (OFF-01 to OFF-10). A live session only reads them; it never refits, retrains or downloads. The learner profile is updated cheaply after each session (LP-02); recalibration is offline.
2. **Rules decide** (ADR-0005, ADR-0008): state changes, critical scoring and action acceptance are deterministic. Models propose, compose, interpret and phrase.
3. **AI composes, rules enforce:** the AI composer (LG-04, an LLM with retrieval over the scenario knowledge base, schema-constrained) proposes the scenario plan; the solver, Stage B and cross-modal rules enforce it. The same pipeline without a model (solver-only plan, template narrative) is the measured baseline and the fallback.
4. **Personalised:** objectives come from the trainee's learning profile (LP-01, LP-03) and change the substance of the case, not only its label.
5. **Practice only:** generated packages carry review status GENERATED_PRACTICE_ONLY; assessment keeps fixed cases.
6. **Offline-first delivery:** a pre-generated validated pool hides latency and covers a missing backend or GPU.

The full architecture (learning from evidence, AI composition, how each modality is produced, consistency, novelty, personalisation, offline versus live) is in `ai_scenario_generation_architecture.md`.

| VR-D-NORMAL | data | Normal values lie inside the reference band and inside the dataset profile p5 to p95 for the population. | LG-07 |
| VR-D-ABNORMAL | data | Abnormal values lie in the band the block demands (mild, moderate, significant, critical) and agree with critical_results limits. | LG-07 |
| VR-D-BORDERLINE | data | Borderline values are within one band-width step of a band edge and are labelled borderline so scoring does not treat them as definite. | LG-07 |
| VR-D-MISSING | data | A missing result is only allowed where the block declares it (sample not sent, lab delay) and must have a visible reason in the EMR. | LG-07 |

## 6. Novelty and reproducibility

Fresh means a coherent, evidence-informed combination this trainee has not met; it never means random values.

| Level | Weight | Fingerprint fields |
|---|---|---|
| structural | 0.5 | scenario family; primary problem type; block ids for PRES, CMB, RSK, ALG, MED, EVT slots |
| clinical | 0.35 | (analyte, band) pairs for abnormal results; imaging finding tags; ECG rhythm; sepsis tier; event ids; trap types |
| surface | 0.15 | persona tags; narrative template id; social context tags; name |

**Distance:** D = sum over levels of weight x (1 - Jaccard(level sets)); weighted Jaccard where items carry weights.

**Accept when:**

- D >= 0.35 against each of the trainee's last 10 sessions
- structural level not identical to any of the last 3 sessions
- deliberate-practice requests may repeat the structural level if the clinical level differs (clinical distance >= 0.3)

**Library check:** report the distance to the nearest library case; an exact structural copy of a library case is allowed only when the pool cannot satisfy the objectives.

**Metrics:** novelty rate (share of sessions meeting the threshold); mean nearest distance; block-space coverage per trainee over time.

**Fallback:** after 5 attempts serve the most novel valid candidate and log LOW_NOVELTY.

**Reproducibility:**

- package id = SHA-256 of canonical(request, seed, pack versions, block library version, prompt version, model digest, content manifest hash)
- named seed streams per stage and slot (seed/stage/slot) so adding a slot does not shift other values
- LLM output is stored in the package; replay never calls the model; regenerating without the stored output can change only narrative fields
