# Audit lane 3: textures and memory (Quest 2)

Written 10 November 2026 (UTC). Desktop and build-report evidence only: **nothing here was measured on a Quest**, and texture changes do not move desktop frame time (the GTX 1660 SUPER is not texture-bandwidth bound at this scale), so no desktop frame-time claim is made for any item below. What can be measured exactly is memory (the Android build report) and, for text, pixels.

## 1. Where the memory actually is (measured: Android build report of the shipped demo APK)

Source: `artifacts/unity/build-demo.log` (the r3 build). Uncompressed usage by category: **Textures 260.5 MB, Meshes 240.2 MB, Shaders 109.6 MB**, other 7.6 MB. Complete build 1.7 GB on disk; the APK is 380 MB.

Texture MB in the build report by folder (305 texture files, 256.7 MB): Hospital 73.9, Environment 58.3 (of which the one sky HDR is 42.7), PatientBay lightmaps 48.1, Rocketbox characters 27.2, Staff/MPFB characters 18.5, **XR Interaction Toolkit sample assets 15.2**, PolyHaven 14.3.

Largest single items: sky HDR 42.7 MB; the PatientBay shadowmask lightmaps 10.7 + 6 x 2.7 MB (16 bits per pixel, the only lightmap data stored at that rate); `ceiling_tile_normal` 3.4; the XR sample `LegibilityMask.png` 4.0 and `DefaultMaterial_AO.png` 2.7.

**Budget:** Meta documents the Quest 2 app limit as **4.4 GiB** (6 GB of RAM in the device, measured as PSS; [Meta memory/RAM guidance](https://developers.meta.com/horizon/essentials/memory-ram/)). The earlier "about 2.5 GB" figure in this lane's brief is wrong. 257 MB of texture data against 4.4 GiB is about 6%; textures are not what limits this app on memory. Meshes (240 MB) and the 1.7 GB player are the larger items, and neither affects frame time directly.

Reachability method: GUID references from the eight build scenes through scenes, prefabs, materials and models, plus the legacy by-name material lookup for FBX files (the patient monitor's `M_MonLCD` is found only that way). 309 of 635 textures ship; 326 (about 324 MB if they were included) do not, including six of the eleven monitor textures that the earlier ASTC override list covers (that override still protects them if a future scene references them). Script: `D:\ProcSenseWork\reports\lane3\` (`tex.json`, `tex_an.txt`).

## 3. Non-power-of-two resampling (found during this audit)

Every text-bearing texture is imported with `nPOTScale: 1` (To Nearest), so Unity resamples non-power-of-two images to the nearest power of two before compressing, **on every platform**: the monitor UI (1044 x 652) becomes 1024 x 512 (vertical resolution down 21%), the posters (1024 x 1448) become 1024 x 1024 (down 29% vertically), and the reception and TV screens (1080 x 1920) become 1024 x 2048. ASTC accepts non-power-of-two sizes, so `nPOTScale: 0` (None) would keep the full resolution. This is the one setting that visibly sharpens clinical text, but it is a global setting (desktop too) and changes the approved look slightly, so it is **not applied**; it is listed for the owner as an option. The extra memory would be small (the monitor UI at 4x4: 1044 x 652 instead of 1024 x 512, about +0.4 MB).

**Verdict (run of 10 November 2026, 11:13 to 11:21 UTC; the Editor's active build target is Android, so the probe overrides the Android import and the loaded formats in the table are the real shipped ones).**

* **The compression format is not the problem; the size is.** Posters ship as ASTC 6x6 with an Android maximum size of 512, which stores them at 256 x 512. Against the uncompressed full-size reference that import measures 37.6 to 39.7 dB with 0.89 to 0.93 of the reference edge sharpness (five posters measured): fine print is slightly soft but legible in the frames I inspected (sheet above). The same ASTC 6x6 at full size (1024 x 1024) measures 50.7 to 53.1 dB with sharpness 1.00, and ASTC 4x4 at full size 60.6 to 61.5 dB.
* **Recommendation for posters:** raise the Android maximum size of the nine posters from 512 to 1024 and keep ASTC 6x6. Cost about +0.55 MB each (about +5 MB in all); 4x4 would add another 0.3 MB each for a gain nobody can see (50 dB to 61 dB). Not applied here: it changes the shipped look (sharper posters) and needs the owner's yes.
* **TV welcome screen:** already stored at 1024 x 2048; ASTC 6x6 costs nothing visible (55.0 dB, sharpness 1.004); 4x4 reaches 64.8 dB. Keep.
* **Monitor UI:** ASTC 4x4 (today) 54.1 dB; ASTC 6x6 would drop to **34.0 dB with 0.43% of pixels visibly off**. This confirms the earlier override: keep the monitor UI at 4x4.
* **Not measured, and why:** `poster_01`, `poster_03`, `poster_06`, `poster_10`, `monitor_labels`, `reception_screen` and `bulletin_board`. In every pose the probe tried (both sides, six directions, every renderer that uses the texture) swapping the texture for plain grey changed the crop by less than 0.2, or the crop had no text, so the texture is not visible from any of them in the scenes the probe loads (probably hidden variants, off screens or occluded). These four posters share their import settings and layout with the five measured ones, so the poster result is expected to hold; the reception screen, notice board and monitor labels stay unverified and need a hand-placed pose or the headset.
* Everything else in the probe is proven by the table: the four import states loaded different formats and sizes (RGBA32, 6x6 at 256 x 512, 6x6 at 1024, 4x4 at 1024) and gave different pixels.
* **Importer state restored:** the probe copied each `.meta` file to `unity/Logs/texprobe_meta_backup` before changing it and restored it byte for byte; `git status -- unity/Assets/Textures` is empty.

## 5. A/B configurations for Sannan (headset only)

* **Anisotropic filtering:** `QualitySettings.anisotropicFiltering` Force Enable (today) vs Enable (per-texture levels) vs Disable, plus `Texture.SetGlobalAnisotropicFilteringLimits(forcedMin, globalMax)` to cap at 4. Read GPU time with OVR Metrics Tool on the floor-heavy corridor view. The effect is expected to be largest where floors fill the view at grazing angles; expect floor sharpness at a distance to change.
* **Sky HDR as ASTC HDR 6x6:** import override on `city_skyline_8k.hdr` (Android, format ASTC_HDR_6x6, max 4096). Check the log for a decompression warning and compare app memory (`adb shell dumpsys meminfo`): it should drop by about 37 MB. If the device lacks the format the memory will rise instead.
