# Quest 2 A/B packs for Sannan (headset-only checks)

10 November 2026. Everything here needs the headset: none of these can be answered on the desktop, and **no Quest result exists yet**. Work through the table top to bottom, one change at a time, always against the production build (`ProcSense-demo.apk` settings = row P0). Setup, OVR Metrics Tool, thermal rules and the CSV layout are in `quest2_sannan_benchmark_guide.md` (sections 2 to 4); this file only adds what to change.

**Rules for every row.** Change one thing, rebuild only when the "Needs rebuild" column says so, run the same 60 s path three times after a 5 minute warm-up (same room, same start pose), record App GPU ms, App CPU ms, FPS, stale frames, GPU level, CPU level and temperature from OVR Metrics Tool, then roll back before the next row. A change is worth keeping only if GPU or CPU time falls clearly (at least 5%, repeatable in all three runs) **and** the look check in the "Look for" column passes; clinical text on the monitors, posters and charts must stay as readable as in P0.

**Where the controls are.**
`R` = runtime preset in the diagnostic APK (`ProcSense-diag.apk`; left thumbstick click cycles presets; the HUD and CSV log the preset id).
`B` = build-time: edit the named field, then rebuild with `python tools/unity/run_unity.py` (variant `diag`; this writes `artifacts/unity/ProcSense-diag.apk`), reinstall with `adb install -r`.
Settings file for the OpenXR fields: `unity/Assets/XR/Settings/OpenXR Package Settings.asset`.

**Reading results.** OVR Metrics Tool overlay and CSV (the reference for GPU/CPU time, levels, throttling). RenderDoc for Meta Quest (Meta's build; capture over MQDH) shows the render passes, load/store actions and viewport regions when a row needs a structural check. Perfetto traces from MQDH show CPU thread and GPU timeline when frame time moves but the cause is unclear.

## Findings that need a decision before the A/B (from the project files, not measured)

1. **Posters and print textures are capped small on Android.** `Posters/poster_01..07, 10..12` have an Android override of max size 512 (source 1024 x 1448, ASTC 6x6), and all 45 non-power-of-two textures are resampled by `nPOTScale: 1`. If any poster or chart carries text that must be readable, this is below the stated quality bar. It predates this round (not changed by the optimisation work). Rows A18 and A19 are the test; the texture lane should confirm which textures hold text.
2. **Forced-On anisotropic filtering** is authored on the Android quality level while 295 textures ask for 8x: a likely bandwidth cost on the Adreno 650 that the desktop cannot show (row A14).
3. **Subsampled layout** is off and eye tracking is off, so A5 and A6 are independent of any eye-tracking permission.
