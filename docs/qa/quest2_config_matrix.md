# Quest 2 optimisation matrix (final, 9 November 2026 UTC; lane A audit plus the results of lanes B, C and D)

Scope: Unity 6000.5.10f1, URP 17.5.0, OpenXR plugin 1.18.0, XR Management 4.7.0, Android IL2CPP ARM64. Values below were read from the project files themselves (not from memory) and checked against the installed package source (`Library/PackageCache/com.unity.xr.openxr@b5b77b4027be`). **Almost every compatible setting was already correct; the only changes from lane A are the XR Performance Settings feature enabled for Android and the new `QuestRuntimeSettings` component (level hints and refresh-rate read-back). Settings that stay off are off on purpose (reasons below).** No Quest frame rate was measured; "Quest-only verification pending" means the setting is configured as far as the editor allows and only the headset can show the effect.

Files read: `unity/ProjectSettings/ProjectSettings.asset`, `QualitySettings.asset`, `unity/Assets/XR/Settings/OpenXR Package Settings.asset` (the `Android` OpenXRSettings block and `MetaQuestFeature Android`), `unity/Assets/XR/XRGeneralSettingsPerBuildTarget.asset`, `unity/Assets/Settings/URP_Quest_Android.asset` and `URP_Quest_Android_Renderer.asset`, `unity/Assets/UniversalRenderPipelineGlobalSettings.asset`, `unity/Assets/Scripts/XR/QuestRenderTier.cs`, scenes and prefabs (camera, light layers, LOD groups).

Status words: **Implemented and verified**, **Already correctly configured**, **Tested and rejected**, **Unsupported**, **Quest-only verification pending**.

## E. Conditional Quest FPS estimate (not a measurement)

* **Baseline:** 20 to 30 FPS reported on the headset earlier; unverified. Nothing in this round was measured on a Quest.
* **What the desktop says:** with both eyes rendered (1832 x 1920, 4x MSAA) the optimised exterior shows **no frame-time gain on this card**: B28 is +3.8% and B29 +3.4% GPU-bound against B20 (6 rounds), although it draws 18% fewer triangles. The desktop card is limited by per-renderer and CPU work, not triangles. Culling CPU was cut from 0.95 to about 0.5 ms per frame and the city was merged to 44 renderers, which halved the desktop loss, but no variant beat B20.
* **What that implies for the Quest, with the uncertainty stated:** the Quest's tile-based Adreno 650 pays for triangles in binning and vertex work, which this desktop does not, so a gain is possible but unproven. The range is **from about 0% (no change, the desktop result) to a triangle-proportional cut of about 10% of frame time**. On 20 to 30 FPS that is roughly **20 to 30 FPS with no gain, to about 22 to 33 FPS at best** from this round's changes. It is **not 72 FPS** (13.9 ms per frame), and nothing here shows a path to 72 without a larger change in what the headset renders.
* **Memory and load, separate from frame time:** about 190 MB less texture memory (monitor textures in ASTC), a smaller shader set (Lit 213 MB to 110 MB), APK 471 MB to 363 MB; these reduce memory pressure and load stalls, not the steady frame time.
* **What decides it:** the headset runs in the Sannan benchmark guide (B20 vs B0 vs B17 vs B28 vs B29 vs B30, CPU vs GPU skinning, Symmetric Projection, Multiview Render Regions final pass, foveation and eye scale with the owner's text-sharpness check, CPU/GPU level hints).
