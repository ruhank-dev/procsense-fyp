# ADR-0018 — Hybrid credit head, two-stage order fallback, plan extras and trap writer (fourth session)

**Date:** 18 October 2026 (fourth session) · **Status:** Accepted for the engineering; every feature stays OFF (no acceptance met) · **Related:** ADR-0005, ADR-0016, ADR-0017, DT-224

## Context
The third-session credit gate was safe on its development sets but credited only about a third of the ordinary sentences. The spoken-order model fallback read back the right item for 70.5 percent of a development set against a 90 to 95 percent target. Four composer capabilities (A4.c2, A5.c2, A7.c2, A8.c2) had no engine hook.

## Decisions
1. **Classifier.** The first reader of the credit gate is a hybrid head (sentence embedding and TF-IDF features in one regression, `server/classify/hybrid.py`); the TF-IDF head stays the second reader and every guard is unchanged. Legitimate credit rose 33.1 to 39.6 percent (v2 test) and 33.8 to 38.2 percent (v3) without critical false credit on any development set. The frozen set v5 (scored once) still showed 1 of 48 critical sentences and 1 of 12 non-assertive sentences credited (the third-session gate also credited 1 of 48), so the target of zero is NOT met on fresh data; the two sentences were fixed afterwards and added to the regression fixture, which makes v5 a development set. The classifier stays OFF; a new frozen set (v6) and the independent set (EX-01) are the way forward. A guard in `safety_gate.py` now refuses to write results when the embedder dropped rows (a saturated Ollama gave invalid numbers once).
2. **Spoken orders.** The fallback asks the kind first and then chooses among the items of that kind, each with a note built from the content (`server/orders/llm_fallback.py`, prompts `orders.kind@1`, `orders.map@2`), with a confidence floor of 0.9 chosen on the development set. Development set 70.5 to 83.6 percent; the frozen v2 set (scored once): correct 76.4 percent, wrong 18.2 percent, 1 of 10 non-orders offered, nothing released without a yes. The model's confidence barely separates right from wrong, so no threshold fixes the 4B's near-neighbour confusions (CRP and full blood count, glucose and finger-prick glucose, CT and MRCP). The gate `order_fallback` stays OFF; the target was not lowered. The grammar also read "send him down to the CT department" as a test order: a defect found on the frozen set, recorded in DT-224, not fixed against it.
3. **Plan extras and trap writer.** Events, what-if branches (A8) and interactions (A4) are chosen by the model only among candidates made by code (eligible events; knowledge-base-linked problem pairs), validated by `plan_extras.validate`, carried in `provenance.plan`, and read by the engine through `SessionOptions.PlannedEvents` (practice mode only; replay-safe). The trap writer rewords only wrong options, keeps ids, flags and consequences, reverts any wording that lowers trap fairness and records `trap_wording`. Measured with the real 4B on the library (reports/ai/plan-extras-eval.json, trap-writer-eval.json): no ineligible event and no refused proposal on 53 cases; interactions on 24 of 53 cases, which equals the number of cases that have a knowledge-base pair at all (the model chose every candidate, so it adds nothing over the code), against the plan's 80 percent; 24 of 98 wrong options reworded, none lowered trap fairness. Relevance and plausibility are human ratings (EX-03) and are not measured. The gates `plan_extras` and `trap_writer` are OFF.
4. **KB extraction** moved to the 4B (ADR-0017).

## Consequences
Nothing is switched on by this change. The engine gains one optional header field. Claims stay labelled synthetic or proxy.

## Revisit if
A frozen v6 set shows zero false credit; an independent set exists; a larger shortlist model or a fine-tuned mapper reaches the order target on a fresh frozen set; raters judge the extras or the reworded traps better than the baseline.
