# ADR-0024 — Ollama Cloud is the inference platform of the semantic speech reader; the model proposes, strict validation and the existing deterministic checks decide

**Date:** 20 October 2026 · **Status:** Accepted for the engineering as a release candidate behind two OFF switches (owner request of 20 Oct 2026, prompt 178; step p1-ai-language-s18). **The final model selection is NOT closed:** `gemma4:31b` is the working implementation target and the only shortlisted model reachable on the free plan; the comparison was approved on 20 Oct but is BLOCKED (`deepseek-v4.1-flash` needs the paid Pro plan, `mistral-large-4` is not rolled out to the account), so no winner was chosen. Independent validation, privacy review, real-audio and Quest testing are NOT DONE. `speech_interpretation` and `interpret_llm_enabled` stay OFF.

## Context
* After ADR-0022 to ADR-0023 the interpretation path is the classifier gate plus deterministic validation. A cloud experiment (`docs/research/cloud_gemma_rubric.md`, commits `cb85431` and `2f82fb7`, local and not pushed at the time of writing) showed that Ollama Cloud `gemma4:31b` credits many more legitimate sentences than the gate (111 to 123 of 140 per split with guards) but that the word-list guards alone let 3 of 40 critical and 1 of 300 adversarial sentences through on `test2`, and that 7 to 21 percent of its replies were fenced JSON, malformed under the strict contract.
* The owner chose **Ollama Cloud** as the inference platform. Self-hosted GPUs and other providers are not the default alternative.

## Decisions
1. **Platform: Ollama Cloud** (direct API `https://ollama.com/api/chat` with a Bearer key, or a signed-in local Ollama relaying a cloud model). Verified 20 Oct 2026 against the public list `https://ollama.com/api/tags` (23 models) and the official pages. Free-tier use only; no subscription, credit purchase or paid usage was created.
2. **Structured output cannot rely on the platform.** The official page states "Ollama's cloud currently does not support structured outputs." Reproduced on 20 Oct 2026 with `gemma4:31b`, 3 sentences: a `format` JSON schema on `/api/chat` and an OpenAI-style `response_format` on `/v1/chat/completions` both returned code-fenced or off-schema JSON (6 of 6 non-conforming). So native constrained generation is **not** available on the intended route. The implementation sends the schema (grounding, and for hosts that do honour it), puts an explicit format instruction and an untrusted-data declaration in the prompt, and **validates every reply strictly** with Pydantic (`server/interpret/llm/schema.py`, `strict.py`, schema version `semantic-reading-1`). Instructor was not added: the dependency would not change this (the provider does not enforce, and retries are three lines).
3. **Strictness.** A reply is a valid `Reading` or it is rejected with a code. Rejected: empty, truncated (`done_reason` other than `stop`), fenced, text around the object, not an object, duplicate keys, any schema violation (missing or extra field, wrong type, value outside an enum, more than two findings), an objective that is not an approved identifier, a duplicated objective, SUPPORTED without evidence that is a verbatim part of the utterance, and SUPPORTED that is not the trainee acting now. Nothing is repaired, stripped or coerced. At most two attempts and a 12 s budget; a retry happens only after a format rejection or a timeout, adds one fixed sentence (no model text echoed), and never after a semantic rejection or a 401, 402, 403 or 429 signal.
4. **Pipeline** (`server/interpret/semantic.py`, built only when `interpret_llm_enabled`): the shipped Interpreter runs first on the same gate result; critical topics, an unavailable classifier, no eligible objective, and every non-performed sentence (denied, planned, hypothetical, reported, another speaker, quoted, retracted, hedged, fragment) are final and **the model is not called** (no cost, nothing leaves the machine). Otherwise the reader's SUPPORTED finding is a candidate: a critical objective gives the menu; several, none or an uncertain reading abstains (a model that does not support the offered act vetoes it); a single non-critical candidate must pass the same deterministic validation as any act (behaviour window, waiting patient question, waiting read-back, behaviour not already credited, assertion status) **and the head's critical-mass cap**, and is offered with the **head's own probability** as confidence, so the engine's per-act thresholds, window, duplicate and critical checks apply unchanged. Any failure of the reader returns the shipped decision with a code. The model never awards credit; physical or procedural credit still comes only from verified simulation events; the engine's EvidenceStore is the authority.
5. **No permanent AND-baseline requirement.** The cap is applied as a *safety veto on the model's candidate*, which is what stopped the `test2` allergy question that the word-list guards missed; the baseline gate does not have to agree on the act. This is not claimed safe: it is the only measured configuration with no observed unsafe credit, on synthetic data.
6. **Configuration and secrets.** `INTERPRET_LLM_*` settings (`server/config.py`, `server/.env.example`): enabled (false), model, base URL, key (a `SecretStr`, never logged, never in a body, never committed), timeouts, attempts. The audit row keeps hashes, reason codes, the model name and rule-set versions, no text.
7. **A mock and a replay provider** make every test and the benchmark independent of cloud availability.

## Alternatives
* **Self-hosting or another provider:** not the default; no blocker found that requires it. The one blocker found is that the cloud route does not enforce a schema, which is mitigated by strict validation, not by changing platform.
* **A native-schema local model for structured output:** possible for local Ollama (not tested here); outside the chosen platform.
* **Strip the code fence and accept:** rejected by decision; it would turn a malformed reply into credit.
* **Model as the final judge, guards removed:** rejected; `test2` showed the guards are needed and word lists are not enough.

## Model candidates (verified catalogue, 20 Oct 2026) and the selection state
Available on the cloud list with `completion`, `thinking`, `tools` (no entry advertises structured outputs): `gemma4:31b` (62.5 GB, 2026-04-02), `deepseek-v4.1-flash` (2026-09-10; also `:1017`, 2026-10-17), `deepseek-v4-pro:0813`, `glm-5.3-flash`, `glm-5.3`, `mistral-large-4` (2026-10-06, size not listed), `mistral-large-3:675b`, `nemotron-3-super`, `gpt-oss:20b` and `:120b`, the Kimi and MiniMax families and others. **Not listed:** any Ministral model; Qwen3.5 397B.
Shortlist proposed (at most three): `gemma4:31b` (historical baseline, measured), `deepseek-v4.1-flash` (newest flash-class model, chosen for latency), `mistral-large-4` (Mistral family, newest). Excluded: `deepseek-v4-pro:0813`, `glm-5.3`, `kimi-k3` and similar (hundreds of GB to 1.5 TB, interactive latency and cost); `glm-5.3-flash` (close to the DeepSeek flash class, kept as the first substitute); `gpt-oss:20b` (measured on 98 dev rows: 19/28 recall, 1/8 critical false credit with guards, 98 of 98 schema failures without the format instruction; `reports/ai/cloud-gemma-rubric.json`); `clef:27b` (a decision model, not a reader). **The comparison could not be done:** a smoke call returned HTTP 402 "not in the Free plan" for `deepseek-v4.1-flash` (and `glm-5.3-flash`, `deepseek-v4-pro`, `kimi-*`, `minimax-m3`, `mistral-large-3:675b`) and HTTP 403 "being rolled out and not yet available to you" for `mistral-large-4`; no paid plan was enabled. Free-plan models that answer: `gemma4:31b`, `gpt-oss:20b`, `gpt-oss:120b`, `nemotron-3-nano:30b`, `nemotron-3-super`, `nemotron-3-ultra`, `beam`, `minimax-m3.1-flash`. Choosing a different shortlist needs the owner's approval (DT-237). Until then `gemma4:31b` is the provisional target and the model name is a setting, not code. **No candidate meets the acceptance criteria**: none is ready. **Free-plan follow-up (20 Oct, approved):** `gpt-oss:120b` and `nemotron-3-super` were evaluated live on the same dev rows (`reports/ai/semantic-live-comparison-dev.json`): recall 79/140 (56.4%) and 88/140 (62.9%) against `gemma4:31b` 92/140 (65.7%); first-attempt validity 99.3%, 79.4%, 97.2%; median latency 1.0 s, 3.5 s, 0.9 s; 0 critical and 0 adversarial offers for all. **`gemma4:31b` is the strongest viable free option and stays the provisional target; no replacement is recommended and no model is ready.** `beam` and `nemotron-3-nano:30b` answer on the free plan but were not evaluated (no clear reason after the first comparison).

## Acceptance criteria and where they stand (engineering targets, not clinical acceptance)
| criterion | target | measured (synthetic, by replay of recorded Gemma replies; dev / test / test2) | status |
|---|---|---|---|
| legitimate recall | at least 85% (independently labelled) | 88, 75, 75 of 140 (63%, 54%, 54%); shipped path 95, 76, 79 | **NOT MET**; no independent set |
| credited precision | at least 95% | 88/89, 75/75, 75/75 | met on synthetic rows only |
| critical false credits | 0 | 0/40 on all three | 0 observed, synthetic |
| adversarial false credits | 0 | 0/300 on all three | 0 observed, synthetic |
| strict schema compliance | at least 99.5% | recorded replies (old instruction): 92.2%, 91.4%, 78.3% valid on the first attempt. **Live dev run (new instruction, 141 requests)**: 137 of 137 replies received valid (100%), 137 of 141 requests = 97.2% because 4 timed out (the per-attempt timeout defect, fixed afterwards, not re-run) | met on replies received in one split; **requests not yet at 99.5%** (timeouts); one split only |
| latency budget | stated | live dev: median 895 ms, p95 1,302 ms, max 1,530 ms over 137 answered calls; 4 of 141 stalled to 12 s; recordings: outliers up to 118 s; the reader's 8 s per-attempt limit and 12 s budget bound a request and the shipped decision answers on a failure | measured on one split |
| fallback and availability | measured | every failure path returns the shipped decision (65 tests); live: 4 timeouts in 141 requests fell back as designed | tests plus one live run |

**The recall target is not reachable with the cap in force.** Of the legitimate sentences the pipeline does not offer, 33 of 49 (dev) and 40 of 62 (test2) are stopped by the head's critical-mass cap, the same sentences the shipped path loses, and 6 and 13 by the critical-cue menu. Relaxing the cap or the thresholds is forbidden without independent evidence. The model's reading cannot remove that ceiling until an independent critical-content signal replaces the head's mass as the protection (DT-238). Measured honestly, the pipeline equals the shipped path on safety and is **below it on recall (-7, -1, -4 sentences)** because the model's veto and different-objective candidates removed more shipped offers than it added. An optional mode (`engine_floor`, DT-236) offers a model candidate at the engine's own threshold; it gives 91, 82, 78 of 140 and is not the default and not approved.

## Consequences
* A complete, tested release candidate exists behind two OFF switches; it does not improve recall over the shipped path and does not meet the schema target on recorded replies. Both are reported, not hidden.
* 65 server tests (strict validator, provider, reader, prompt, interpreter policy, concurrency, wiring, budget guard) run without the cloud; 18 mutants of the new code are killed (`tools/ci/mutation_safety.py`).
* **Live evidence (20 Oct, dev, 488 rows, `gemma4:31b`):** only 141 rows reached the model (192,698 tokens, about 0.5 percent of the allowance, estimated); pipeline recall 92/140 at precision 92/93, critical 0/40, adversarial 0/300, out-of-window 0; shipped path 95/140. The live run found a timeout defect (a stalled first attempt used the whole budget), fixed with a regression test and a mutant.
* Unresolved: the model comparison, the live schema-compliance measurement, the privacy and consent decision for sending trainee speech to a third party (`server/PRIVACY.md`, DT-127), independent labels (EX-01), the audio path, Quest.

## What this does not show
Synthetic builder-written labels; a baseline tuned on these splits; `test2` previously used by the Qwen experiment; the recorded replies used the bare prompt, so the effect of the scenario context in the new user prompt is unmeasured; no human review, no real audio, no Quest, no clinical validity; zero observed unsafe credits is not a safety guarantee.
