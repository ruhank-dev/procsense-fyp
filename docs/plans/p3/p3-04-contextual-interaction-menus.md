# p3-04-contextual-interaction-menus — Menu-based mode: select a person or object, get its actions (CTX)

Status: Planned (P3, 7 November 2026). Nothing in this plan is implemented.

## 1. Objective and final user-facing behaviour

In menu-based mode the whole session can be finished with the controllers. Pointing at the patient, a nurse, a doctor, the anaesthetist, the receptionist, a porter, a piece of equipment or the records highlights it softly; pressing the trigger opens a glass panel beside it with only the actions that make sense for that person or object **now**. An action the engine would refuse is shown greyed with a one-line reason (for example "Identity not confirmed"). Choosing an action makes something visible happen: the person answers (voice and subtitle), turns to the player or nods, equipment changes state, a checklist item ticks in training. The tablet stays as the complete list for anyone who prefers it.

## 5. Architecture and integrations

- **Catalogue (data, not code):** `content/ui/interactions.json`, generated by extending `build_tablet.py`, maps each entity type to groups of tablet entry ids, plus per action: icon, short label, voice examples (used by P3-VOX), and `confirm: true` for consequential actions (submit, sign consent, postpone). No clinical rule lives in it.
- **Availability:** for each visible action the panel asks `ActionGateway.Preview(request)` → `Session.Check` (P3-SES-02). Results are cached per engine step, so the panel does not query every frame.
- **Entity map (first version, derived from the tablet tabs and verbs):**

| Entity | Groups (tablet tab → verbs) |
|---|---|
| Patient | Admission (introduce_self, ask_identity, read_name_to_patient, read_wristband, confirm_identity, report_mismatch, ask_allergies, ask_allergy_reaction, ask_reason_for_admission, ask_responsible_adult); Ask (ask ×12, summarise, answer_question); Assess (attach/detach_sensor, measure_nibp, measure_temperature, count_rr, assess_acvpu, ask_pain_score, ask_exam_permission, offer_chaperone, examine, murphy_test, airway_check); Consent (consent_discussion ×7, teach_back, check_capacity, sign_consent, request_interpreter); **Submit patient to OT** (P3-EXM-04) |

| Doctor (registrar / surgeon) | escalate (SBAR), say_concern, declare_outcome, postpone, redirect, decide_ready, order_investigation, request_medication |
| Anaesthetist | request_anaesthetic_review, tell_anaesthetist, assess_risk, assess_vte, compute_score |
| Receptionist / porter | request_transport, use_emergency_route |
| Monitor and bedside equipment | attach/detach_sensor, measure_nibp, perform_bedside_test, acknowledge_alarm |

- **Pattern:** catalogue-driven views (data in content, one generic panel). Chosen so that adding an action never needs a new panel.

## 7. Dependencies and execution order

P3-CTX-01 (data) and P3-CTX-02 (scene components) first and in parallel; then selection, the panel, placement and feedback.

## 8. Frontend components

Highlight outline, contextual glass panel (header, groups, action rows with icon and state), confirmation dialog for consequential actions, reason tooltip, wrist menu entry for the tablet.

## 9. Backend and API changes

None.

## 10. AI and voice integration

The same catalogue feeds the voice reference panels (P3-VOX-04); the same gateway receives both.

## 11. Unity objects, prefabs, animations and assets

`Interactable` on scene objects; `ContextPanel.prefab`; icon atlas (P3-UIX-06); highlight material (shared, SRP-batcher compatible).

## 12. Performance

One panel open at a time; panels are pooled; availability cached per engine step; highlight uses a material property block, not a second camera or post effect.

## 13. Error handling and edge cases

Entity out of view or in another room (panel closes); patient away for imaging (patient actions show "The patient is in CT"); two panels requested at once; action with parameters cancelled; engine refuses after a stale preview (outcome reason shown, nothing applied).

## 14. Testing

Validator and tool tests (Python), EditMode for availability mapping, PlayMode for selection and placement in the three rooms, Editor captures for review.

## 15. Acceptance criteria

1. Every action needed to finish S1 and S2 in the golden runs is reachable from a contextual panel without the tablet.
2. A greyed action always shows the engine's reason.
3. No contextual panel shows an action for the wrong entity (catalogue test).

## 16. Definition of Done

All CTX tasks Done, golden playthrough by menu only recorded on desktop, headset item in DC-14.
