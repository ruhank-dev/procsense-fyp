## Naming convention

```
docs/plans/
├─ p0/                                   tier folder
│  ├─ README.md                          tier overview
│  └─ p0-core-engine/                    phase folder  = <tier>-<phase>
│     ├─ README.md                       phase plan
│     └─ steps/
│        └─ p0-core-engine-s01-sim-clock.md     step = <tier>-<phase>-s<NN>-<slug>.md
└─ …
```

- Every phase folder and every step file **starts with its tier** (`p0-`, `p1-`, `p2-`), so a file seen on its own still shows where it belongs.
- Approved step → renamed `✅ p0-core-engine-s01-sim-clock.md`.
- Experiment IDs: `EXP-<PHASE>-<n>` (e.g. `EXP-CORE-1`), recorded in that phase's README.

## Environment principle

**Fully model what the trainee actually learns and interacts with. Simulate/abstract everything else.**

| Category | Locations |
|---|---|
| **A — fully modelled + interactive** | Operation Theatre (main environment) · one pre-op patient bay (S1 ward / S2 ED) · walkable corridor · desk + computer inside them |
| **B — transition / report-only** (doors along the corridor; trainee can't enter) | CT Scan · Imaging/Ultrasound · X-ray · Laboratory (samples only) · MRCP/ERCP · specialty redirect |
| **C — computer / UI only** | Previous history, previous + current reports, labs, images, NEWS2 trend, drug chart, handover form |

Details: [p0-environment-rooms](p0/p0-environment-rooms/). Review of the phase list: [phase-review.md](phase-review.md).

## How the plan changes as we learn

1. Every phase lists **experiments** with a success metric; results are written into that phase's README.
2. If a result beats the current decision → ADR in `docs/decisions/`, Decisions table updated (old choice moves to
   "alternatives" with why it lost), user informed.
3. Every decision has a **"revisit if"** trigger.
4. A decision with alternatives is always shown to the user with both options.

## Medical approval status (decision of 09 October 2026)

The project owner has instructed that **all existing medical research and clinical workflows are treated as clinician-approved**, and that the trust/anxiety ±1 values are acceptable simulation mechanics.
Consequences: no further "pending approval" flag is kept on existing research or workflow rows; the source register's `clinician_approval` column records "Approved … per project owner". 
Still required for every **new** clinical value or rule: a source-register row (proof of truth), and a recorded value for hospital-specific choices that the approval statement does not supply
(see DT-018 in [../deferred-tasks.md](../deferred-tasks.md)). Source conflicts (e.g. ISS-0001, ISS-0002) stay open until the owner closes them. The walkthrough's own text still says "READY FOR CLINICIAN VALIDATION"; that wording is the original and is left unchanged — see `docs/context/ProcSense_Change_Report.md` §G.
