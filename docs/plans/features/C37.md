## 1. Intended user experience

What the trainee says is recognised as communication acts that count in the debrief only when they fit the moment of the scenario; an unclear sentence gets one short question, then the menu; nothing critical is ever credited from speech.

## 2. What exists and what is missing

**Exists in the repository:**

- classifier gate: hybrid embedding head + TF-IDF agreement + critical-mass cap + critical cues + assertion check (server/classify, ADR-0020)
- EvidenceStore.Submit: critical refusal, per-act threshold, step-window check (engine; called only by tests)
- character context builder with recent turns (E54)
- act benchmark tests/action_bench_v1 and the labelling kit for an independent set (synthetic, not independent)

**Missing:**

- typed interpretation context from the session and state-based eligibility (p1-ai-language-s10)
- speech evidence in the session log, duplicate check, behaviour by window (s10)
- interpretation service with deterministic validation and decisions (s11)
- clarification, menu fallback and failure handling, Unity half (s12)
- context-conditioned benchmark, end-to-end latency, speech_interpretation gate (s14)
- independent human-labelled set (EX-01)
- independent evaluation of the revised critical-mass cap and the calibrated engine thresholds (p1-ai-language-s15, DT-231, EX-01)
- independent human review and the independent run of the unsafe-speech sets, and the residual mechanisms found by the one-time scoring of the final split (p1-ai-language-s16, EX-01, DT-233, DT-234)
- blind human review and the independent run of the unsafe-speech sheet, the audio-to-transcript evaluation (design only), and a fresh final set for any fix of the DT-233 mechanisms (p1-ai-language-s17, EX-01, DT-233, DT-234, DT-235)

**Deterministic foundation:** Eligibility from the behaviour windows of content/assessment/mapping.json, assertion status, critical exclusion, evidence span and duplicate checks, and the engine's EvidenceStore as the only authority.
