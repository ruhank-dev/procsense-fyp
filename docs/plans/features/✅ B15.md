## 1. Intended user experience

The monitor and the ECG printout match the patient: AF looks irregular at the right rate; a high potassium shows the expected changes when the case teaches it.

## 2. What exists and what is missing

**Exists in the repository:**

- PTB-XL templates (sinus, tachycardia, AF)
- real strips with reports
- labelled synthetic ECG pictures

**Missing:**

- rate and noise variants
- class coverage for needed rhythms
- learned or model-based waveform generation

**Deterministic foundation:** Rhythm and rate slots set by the case; measurement check.

## 3. The AI in this feature (seven questions)

| Question | Answer |
|---|---|
| 1. What is the AI supposed to do? | Generate a waveform with the requested rhythm and rate that looks like a real recording. |
| 2. Why is AI useful here? | Real strips cannot match every rate; a generative signal model produces variants with realistic morphology. |
| 3. Which method for which part? | Model-based generation (NeuroKit2 ECGSYN dynamical model) and template morphing first; a learned waveform generator only if the profile study shows the parametric model cannot match needed classes. |
| 4. Deterministic parts still needed | Rhythm and rate from the case; measurement validation. |
| 5a. AI already implemented | None. |
| 5b. AI missing | Parametric generator; optional learned generator. |
| 6. What we must build | Variant renderer; QRS-detector validation; optional conditional generative model evaluated against PTB-XL. |
| 7. How we prove it beats a simple baseline | Blind real-versus-generated discrimination by raters near chance and automatic feature distances (rate, intervals) within PTB-XL class ranges. |
