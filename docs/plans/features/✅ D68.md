## 1. Intended user experience

The next case is chosen or generated to practise what the trainee needs, changes the substance (problems, traps, investigations, events), and the trainee can read why.

## 2. What exists and what is missing

**Exists in the repository:**

- Selector over existing cases

**Missing:**

- objective derivation from the learner profile
- contextual bandit policy
- objectives handed to the AI composer
- explanations
- offline evaluation

**Deterministic foundation:** Valid set, difficulty bounds, novelty constraints, assessment exclusion.

## 3. The AI in this feature (seven questions)

| Question | Answer |
|---|---|
| 1. What is the AI supposed to do? | Choose learning objectives and scenario features that maximise expected learning for this trainee; explain the choice. |
| 2. Why is AI useful here? | Static rules cannot balance practice of weaknesses, spacing, novelty and difficulty; a bandit learns which scenario features produce improvement. |
| 3. Which method for which part? | Rule-based targeting first; contextual bandit (Thompson sampling over scenario features with the learner profile as context) once data exists; LLM writes the explanation; composer receives objectives. |
| 4. Deterministic parts still needed | Valid set, bounds, exploration caps, safety (practice only). |
| 5a. AI already implemented | None. |
| 5b. AI missing | Policy, objectives, explanation, evaluation. |
| 6. What we must build | p1-personalisation s03, s05; LG-02 integration. |
| 7. How we prove it beats a simple baseline | Off-policy evaluation and simulated learners: bandit versus rule targeting versus Elo selection on learning gain. |
