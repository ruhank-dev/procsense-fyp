## 1. Intended user experience

| Field | Value |
|---|---|
| Kind | AI (LLM) |

| Data | — |
| Input schema | `trigger + context` |
| Output schema | `line` |
| Processing flow | queue picks → prompt → validator → speak |
| Validation of outputs | Grounding. |
| Errors | Timeout or server error: one retry, then fixed reaction line; logged with prompt version and model digest. |
| Hallucinations | Output must match a JSON schema whose enums are approved ids; the grounding validator rejects invented drugs, values, diagnoses, events and hidden facts. |
| Inconsistent results | Output is cross-checked against the structured case or facts it was given; any mismatch rejects it. |
| Model unavailable | Feature switch reports off; fixed reaction line. The session never waits on the model. |
| Invalid input | Inputs are schema-validated before the model is called; invalid input is a 4xx with field errors. |
| Tests | trigger timing; naturalness |
| Metrics | naturalness |
| Baseline comparison | Fixed lines. |
| Acceptance | Higher naturalness; fires on trigger step only. |
| GTX 1660 SUPER (desktop) | Desktop GTX 1660 SUPER (Turing, 6 GB, no tensor cores), measured 16 Oct 2026 with the machine idle: qwen3.5:4b-q4_K_M (3.3 GB weights, thinking off) sits 100 percent on the GPU (3.1 GB at a 4k context) and generates about 59 tokens per second, a 50-token patient reply taking about 1.0 s (p95 1.15 s); qwen3.5:9b-q4_K_M (6.6 GB) does not fit and runs 57 percent on the GPU with the rest on the CPU, about 12 tokens per second and about 5 s for the same reply, so it is the offline batch model only.
