## 1. Intended user experience

The trainee presses 'New practice case'. Within seconds (from the pool) or under a minute (live) a case starts that they have not seen, targets what they need to practise, and plays exactly like a hand-made case; the debrief says why it was chosen.

## 2. What exists and what is missing

**Exists in the repository:**

- deterministic pieces each stage reuses: Stage B, band sampling, imaging library, Elo ratings, EventDirector, grounding validator, replay

**Missing:**

- all 21 stages as a pipeline
- AI scenario plan composer
- learned conditional generation
- knowledge base
- personalised objectives
- package and pool

**Deterministic foundation:** Solver, Stage B, cross-modal rules, seeded generators and the Core decide validity and state.

## 3. The AI in this feature (seven questions)

| Question | Answer |
|---|---|
| 1. What is the AI supposed to do? | Compose a coherent new scenario plan from objectives, history and evidence; write the narrative and dialogue texture; judge coherence; interpret the trainee's needs. |
| 2. Why is AI useful here? | Fixed cases cannot cover every combination of needs; random recombination produces incoherent or repetitive cases; an AI composer that reads the knowledge base and exemplars can produce varied, causally coherent cases and explain them. |
| 3. Which method for which part? | LLM + retrieval: scenario plan and narrative. Statistical (learned conditional models): numbers. Retrieval + parametric transforms: images, ECG. Deterministic: solver, validation, novelty, packaging, state. Bayesian learner model + bandit: targeting (D67, D68). |
| 4. Deterministic parts still needed | Everything that decides validity or state. |
| 5a. AI already implemented | None. |
| 5b. AI missing | Composer, narrative, judge, learned conditional generation, personalised targeting. |
| 6. What we must build | Stages LG-01 to LG-21 with the AI composer (LG-04), learned generation (LG-07), the judge (LG-11), and the learner profile (LP-01 to LP-03). |
| 7. How we prove it beats a simple baseline | Paired study on simulated and pilot trainees: AI-composed personalised cases versus random valid recombination: higher coherence ratings, higher novelty at equal validity, and larger improvement on targeted competencies. |

### A2.c2 — AI scenario plan composer (live)

| Field | Value |
|---|---|
| Kind | AI (LLM + retrieval + solver) |
| Status | Implemented but incompletely tested |
| Purpose | Propose the scenario plan (problems, investigations, decisions, traps, events, branches, outcomes) for this trainee. |
| Architecture and model or algorithm | Qwen3.5 9B with JSON schema over KB concept ids; retrieval of KB subgraph and 3 exemplar cases; solver completion; rationale per choice. |
| Models | MC-01 |
| Data | ST-KB; ST-BLOCKS; ST-LEARNER |
| Input schema | `Objectives v1 + KBSubgraph + exemplars` |
| Output schema | `ScenarioPlan v1 {family, primary_problem{id,type}, secondary_problems[{id,type}], comorbidities[], medications[], allergies[], investigations[{test_id, expected_finding_tags[], band_targets{analyte:band}}], decision_points[{id, step, correct_option_ids[], trap_option_ids[]}], events[{event_id, trigger, window_s}], branches[{decision_id, option_id, consequence_id}], outcomes[{end_state, conditions}], teaching_points[], rationale_per_choice{}}` |
| Processing flow | LP-03 objectives → LG-03 retrieval → LG-04 LLM proposes plan → solver completes and checks → LG-05 skeleton → defects loop via LG-12 (max 3) |
| Validation of outputs | Schema enums; every relation used must exist in the KB with confidence at least medium; solver; Stage B; VR-CM. |
| Errors | Timeout or server error: one retry, then solver-only plan from the same objectives; logged with prompt version and model digest. |
| Hallucinations | Output must match a JSON schema whose enums are approved ids; the grounding validator rejects invented drugs, values, diagnoses, events and hidden facts. |
| Inconsistent results | Output is cross-checked against the structured case or facts it was given; any mismatch rejects it. |
| Model unavailable | Feature switch reports off; solver-only plan from the same objectives. The session never waits on the model. |
| Invalid input | Inputs are schema-validated before the model is called; invalid input is a 4xx with field errors. |
| Tests | schema validity; KB-relation compliance; blind coherence rating versus solver-only; latency on both GPUs |
| Metrics | valid plan rate; coherence rating; structural novelty; objective coverage |
| Baseline comparison | Solver-only plan with random tie-breaks (A2.c1). |
| Acceptance | Coherence and objective coverage higher than baseline (paired, p under 0.05) at equal Stage B pass rate; p95 under 25 s or served from pool. |
| GTX 1660 SUPER (desktop) | Desktop GTX 1660 SUPER (Turing, 6 GB, no tensor cores), measured 16 Oct 2026 with the machine idle: qwen3.5:4b-q4_K_M (3.3 GB weights, thinking off) sits 100 percent on the GPU (3.1 GB at a 4k context) and generates about 59 tokens per second, a 50-token patient reply taking about 1.0 s (p95 1.15 s); qwen3.5:9b-q4_K_M (6.6 GB) does not fit and runs 57 percent on the GPU with the rest on the CPU, about 12 tokens per second and about 5 s for the same reply, so it is the offline batch model only. Speech recognition and the Unity Editor were not loaded in these runs; the laptop RTX 4050 is not measured. |
| RTX 4050 Laptop | Laptop RTX 4050 (Ada, 6 GB, tensor cores, power-limited): faster per token than the desktop for the same model, but if Unity VR renders on this GPU the model must share VRAM with the scene; budget about 2 GB for a model while Unity runs, or run the model on the desktop. |
| Memory | 16 GB system RAM on the desktop limits CPU offload to small models; laptop RAM to be recorded in the benchmark. |
| Latency | Interactive replies: p95 under 3 s; generation stages: under 25 s or served from the pre-generated pool; offline jobs: no limit. |
| Deployment | Recommended split (to confirm by p1-ai-infrastructure-s02): inference service on the desktop GPU, Unity on the laptop GPU, over the local network. Single-machine mode: Qwen3.5 2B (to be benchmarked) or CPU inference plus the pool. Remote inference only for offline jobs, never with real personal data. |
