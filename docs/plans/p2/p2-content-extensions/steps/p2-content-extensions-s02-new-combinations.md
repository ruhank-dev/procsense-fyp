# p2-content-extensions-s02 — New combinations with the 14B.5 recipe

Milestone: **M13 P2 extensions**

## What
Compose new multi-problem cases following the walkthrough recipe (each problem typed, ranked, checked, with end state, clock and handover items); approval is optional (ADR-0008).

## Why
Once the walkthrough's cases are all built, new combinations give trainees fresh practice — but only if each follows the walkthrough's recipe and is clinically approved.

## How to implement
1. Composer + recipe enforcement; review.
2. Pick target problem combinations from gaps in the P0/P1 pool (e.g. diabetes + anticoagulant + fasting breach).
3. Composer builds candidates; each must list problems, types, ladder order, checks, end state, clock and handover items (14B.5).
4. Stage B + golden correct path; review pack; approved ones enter the practice pool only.

## Status (18 October 2026, third session)

- **Built: the composition engine** (`tools/composer/multiproblem.py`, rules in `tools/composer/composition/rules.json`, `task compose-multiproblem`). It follows the recipe of walkthrough 14B.5 step by step from the problems of approved cases: each problem is a module (type, label, expected actions, source case and problem); modules are ordered by the ladder (life threat, safety blocker, time-critical, pathway-changing, optimisable, information-only); the seven cross-check categories the chosen problems touch are listed; the end state follows recipe step 5 (S1 with an optimisable problem ends postponed, otherwise the most diverted end state of the sources); the deterioration clock is set by the first problem of the ladder; the handover items are every problem, action and stated time. Coherence rules: one scenario, 2 to 4 problems, at most 3 life threats, no two problems from the same source case, no repeated topic, no action that one problem forbids and another requires, sex and age requirements must not conflict (pregnancy needs a female patient, "a minor" a minor), and the combination must be new (its topic set is not that of any authored case).
- **Output:** `tests/composition/compositions.json`, 12 synthetic DRAFT fixtures with a stable schema, labelled `clinically_validated: false` and `practice_only: true`. They are planning structures, not case files: they hold no observation, result, history or medicine of their own.
- **Tests:** `tools/composer/test_multiproblem.py` (12 tests: each rule rejects, the ladder order, the end-state rule, the schema, determinism by seed, traceability to approved sources, tampering is caught, nothing claims clinical validation) and `multiproblem.py --check` run in CI.
- **Still missing, and why:** the authored content. A combination becomes a case only when every value (observations, results, history, medicines, timings, the decisions) is written from the sourced tables with a source row, then passes Stage B and the golden runs (DT-220, EX-13). A clinician's approval is not the blocker under ADR-0008.
