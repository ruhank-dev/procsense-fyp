# p1-ai-language-s10 — Interpretation context and state-based objective eligibility (engine)

Milestone: **M10 P1 platform — backend, AI, voice input**

## What
The engine builds a typed, read-only `InterpretationContext` for one trainee utterance from the real session, and accepts speech evidence as a logged, replayable entry checked by `EvidenceStore` (ADR-0022, decisions 2 and 6):

| Field | Real source |
|---|---|
| `case`, `scenario`, `mode` | `Session.Case`, `Session.Mode` |
| `steps` | the workflow step numbers of the running flow stages (`FlowSubsystem.Running()` → `FlowStageDef.Steps`) |
| `eligible` | every non-NONE act of `content/assessment/taxonomy.json` that is an `ai_act` of a behaviour whose `steps` window contains one of `steps` (`ScoreTables.Behaviours`), with that behaviour id and whether the act is critical |
| `accepted` | the behaviours already credited from speech in this session (duplicate prevention) |
| `patient_question_pending` | the consent subsystem's pending question (the condition of `answer_question`) |
| `readback_pending` | an instruction or result from a colleague not yet read back (the `read_back` condition) where the engine records one; `false` otherwise (stated, not guessed) |
| `last_turns` | the last four turns with their speakers (`ContextBuilder` turns), trimmed to a token budget |
| `speaker`, `addressee` | the trainee; the character addressed (patient or a staff role) |

It holds no hidden fact, expected answer, score or goal list. Speech evidence: a `speech_evidence` action (`act`, `behaviour`, `span`, `status`, `confidence`, `utterance_id`) applied through `Session.Apply`; `EvidenceStore.FromLog` submits it through `Submit`, which gains two checks: `DUPLICATE` (the behaviour already credited from speech for the same utterance or act) and the behaviour chosen by window (an act listed by two behaviours, CLARIFY in b03 and b19, ESCALATE_SPEECH in b15 and b20, goes to the behaviour whose window contains the step, not the first in the file).

## Why
The classifier saw a sentence alone; the engine's window rule and the pending-question condition were never applied before credit, and speech never reached the log, so the debrief could not show it and replay could not reproduce it.

## How to implement
1. `src/ProcSense.Core/Speech/InterpretationContext.cs` (record + `ToJson()` in a fixed key order) and `InterpretationContextBuilder.cs` (reads the session; no write path).
2. `Session`/a subsystem registers the `speech_evidence` verb (no state change; not in any behaviour's `actions`, so it can never be procedural credit).
3. `EvidenceStore`: behaviour by window, `DUPLICATE`, and `FromLog` reading `speech_evidence` entries.
4. Shared test vectors (`tests/vectors/interpretation_context/*.json`) so the Python service validates the same payload.

## Verification
xUnit: eligibility per step for every behaviour of `mapping.json`; an out-of-window act rejected; a critical act never accepted in any step; duplicate rejected; CLARIFY and ESCALATE_SPEECH credited to the in-window behaviour; replay of a log with `speech_evidence` gives the same evidence; the context has no hidden fact (the S1 and S2 cases); `speech_evidence` cannot satisfy a behaviour's `actions`.

## Common issues
Several flow stages running at once (parallel tracks): use the union of their steps. A stage with no steps: no objective is eligible (abstain), never "all".
