# p1-live-scenario-generation-s10 — Packaging, pre-generated pool and Unity delivery (LG-14, LG-15)

Milestone: **M14 P1 live scenario generation — dataset analysis and fresh cases**


## What
Canonical ScenarioPackage with SHA-256 and provenance; batch pre-generation into a local pool; Unity loads a package through the existing bridge and ContentGate with review status GENERATED_PRACTICE_ONLY.

## Why
Offline-first delivery; latency hidden by the pool.

## How to implement
1. `server/generation/package.py`, pool CLI.
2. C# loader extension and ContentGate status (Core), then Unity bridge (Unity work).

## Status (17 October 2026)

- **Built (Core):** the status `GENERATED_PRACTICE_ONLY` (loader, `ContentGate`, schemas, ADR-0006 amended: extended, not loosened); `ScenarioPackageReader` (`src/ProcSense.Core/Content/ScenarioPackage.cs`) reads a package as a content folder of one case file in front of the real content, refuses any other status, and gives the host the file hash for the session header; `MiniJson.Write`; `CaseFile.TableKey` so discovery, imaging, infection, deterioration and end-state surfacing find a composed patient through its spine; the command line takes `--scenario <package>` on run, replay, report and verify.
- **Built (server):** `package.file_text/write/file_sha256` (the same package is always the same bytes), `server/generation/pool.py` and `tools/generation/pool.py` (a pool of one story per spine per family and level, byte-identical for the same seed, each package checked against the pool index and its seal before it is served, a pool made from other content refused); Stage B checks 9 and 10 now run for a generated case from a package file against the spine's correct-path script and expected end state.
- **Verification result:** 1263 C# tests pass (`ScenarioPackageTests`: reads as a folder, gate allows practice and refuses assessment, a package cannot raise its own status, the spine's correct path plays the new patient, loads in well under 2 s); `tools/ci/test_generation_package.py` (9 tests): byte-identical files and pools, serving suits the request and skips met stories, a changed file or stale pool is never served, six generated packages play through the real engine and the command line refuses assessment and replays the log. 60 of 60 sampled generated cases pass the idle run and the correct path.
- **What the headless check found:** a composed case from VAR-S2-G with a penicillin allergy failed its own correct path (the correct path gives an antibiotic, the case text does not say so). Spines are now tagged `pathway:antibiotic` from their correct path as well as their text, so that allergy is never composed with them; and the checklist allergy answer follows the composed patient.
- **Server verification:** `SessionVerifier` now loads the package the log names (it was a refusal, PACKAGE_LOADER_MISSING): the package bytes must match the header hash (line endings normalised, raw bytes accepted), be a GENERATED_PRACTICE_ONLY package of the log's case, and the session is replayed with the real content behind it; the report of a verified session carries the `generated` section with the package hash. The backend already stores packages by hash (`PUT /scenario-packages/{hash}`), so an uploaded session of a generated case can now be verified end to end (tested in C# and through the command line).
- **Not built:** the Unity bridge and the picture display (Sannan, DT-198); the HTTP endpoint and the server image (DT-199); electronic-record history for a composed patient (DT-200).
