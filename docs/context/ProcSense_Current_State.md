## 1. What it is
A Meta Quest 2/3 VR trainer (Unity 6000.5.10f1) for pre-operative preparation with invented patients: S1 planned cholecystectomy, S2 emergency appendicectomy. A deterministic C# engine (`src/ProcSense.Core`, version 0.0.17, replay-hash locked) decides every state change and every score. A FastAPI backend (`server/`, PostgreSQL, Docker) holds accounts, sessions, verification (it replays each uploaded session with the same engine) and the AI gateway. Content is data (`content/`, 65 case files, manifest-sealed), built by Python tools (`tools/`). **AI never decides state or score** (ADR-0005): rules decide, models interpret and phrase, and the engine validates every action.

## 3. The AI architecture (who does what)
| Model | Where | Used for |
|---|---|---|
| **Gemma 4 31B Cloud** (`gemma4:31b-cloud`, Ollama Cloud free plan, relayed by the signed-in local Ollama) | `content/ai/model_routes.json` | Semantic reading of speech and spoken orders (`speech.action`, `orders.interpret`, `evaluate`); the patient, staff and nurse voices (`dialogue.*`); scenario narrative, text critic, scenario judge, trap reword (synthetic data). Live budget 4 s. |
| **Qwen3.5 4B** (`qwen3.5:4b-q4_K_M`, local, Apache-2.0) | default for every route and the fallback of the Gemma routes | Plan composer, debrief rewrite, personalisation, analytics explanation; the local fallback of the dialogue routes. The 9B was retired (ADR-0017/0019). |
| **Offline grammar** | `server/orders/grammar.py` | The conservative fallback of spoken orders (word-list question guard, trigger words, fuzzy match, read-back). |
| faster-whisper `small.en`, Piper | `server/asr`, `server/tts` | Speech to text, text to speech. |
The classifier (embeddings/TF-IDF heads) was **removed** (ADR-0025); speech is judged by the Gemma evaluator against the simulator's state and evidence, and the engine turns that into a graded score (critical physical actions never get credit from speech).
Routing (ADR-0026/0027, `server/llm/routing.py`): a cloud route is used only if `CLOUD_ROUTING_ENABLED`; synthetic-class routes then need nothing more; **trainee-class routes need either `CLOUD_SYNTHETIC_DEPLOYMENT` (the demonstration) or `CLOUD_TRAINEE_DATA_APPROVED` (institution) plus that person's own recorded, withdrawable cloud consent**. One cloud request at a time; a failed or slow cloud call falls back to the local model (or, for spoken orders, the grammar).
**Gates** (`content/ai/thresholds.json` → `features.json`, generated by `tools/eval/ai_gate.py`; a feature is ON only if every suite passes): ON — asr, critic, debrief_ai, interpreter, multi_agent, narrative, order_fallback (demonstration waiver, below), patient_dialogue, plan_composer, speech_actions, speech_evaluation, tts, voice_orders. OFF — plan_extras (45 percent of cases against 80), trap_writer (needs two human raters, EX-03).

## 4. Spoken orders (B23, C32; ADR-0028)
Path: recogniser text → `POST /orders/organisations/{id}/hear` (+ scenario context) → **one Gemma call** with the approved action catalogue (tests, medicines, places, staff, home medicines) → structured answer (kind: order/question/hypothetical/negated/ambiguous/incomplete/unsupported/other, intent, item, confidence, clarification) → catalogue and intent-kind check → read-back + **signed, single-use, per-user ticket** → `POST …/confirm` with the trainee's own *yes* → the headset sends the action → **the engine validates and scores**. Ambiguous or incomplete sentences make a question and no ticket. "Can I…" is not rejected by a word list any more.
- **Cloud first, grammar as fallback** (`server/orders/cloud_interpreter.py`): the answer counts only if the cloud model gave it; with the cloud off, unapproved, unconsented, busy, slow or failing the grammar answers (the local model's reading, 69.5 percent, was never the accepted one and is not used). Every answer says which system read it: `interpreter` (`gemma_cloud` | `offline_grammar`), `interpreter_model`, `interpreter_reported_model` (the host's own name for the model, `gemma4:31b`), `fallback_reason`; also the log line, the audit row and `/ai/health` → `routing.spoken_orders`.
- **Demonstration profile:** `server/demo/synthetic-fyp-demo.env` (`task server-demo`) = `CLOUD_ROUTING_ENABLED=1`, `CLOUD_SYNTHETIC_DEPLOYMENT=1`, approval 0, `APP_ENV=dev`. Defaults everywhere else stay OFF; the service refuses to start with the synthetic declaration beside `APP_ENV=prod` or the trainee-data approval. `task demo-orders-check` proves with the real Gemma that it answers and that each fallback falls back.
- **Evidence:** frozen AI-authored held-out set of 151 sentences (`tests/orders/ai_authored`, `reports/ai/orders-ai-heldout_v1.json`): 97.4 percent as labelled, 0 wrong items, 0/50 non-orders offered, 0 confirmation bypasses, 2 safety-related over-proposals (vague sentences), median 0.74 s. Sets are **AI-authored synthetic, not human-authored**. EX-18 (human-authored set) was **waived for the FYP demonstration by the project owner on 26 Oct 2026 (`reports/ai/ex18-owner-waiver.json`), not done** and stays `NOT RUN`. Real trainee use and clinical deployment are **not** authorised by it.
- **Not wired:** no Unity script calls `/orders`; the headset's spoken path is the speech-action route (`/speech/organisations/…`, tablet actions) plus the speech evaluation. Headset checks DC-08/DC-11 are Sannan's and **NOT RUN**.
